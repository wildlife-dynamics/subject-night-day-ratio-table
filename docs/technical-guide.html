Run form

spec.yaml shapes the form in these ways:

  • rjsf-overrides turns Subject Group Name into a drop-down: the EarthRangerEnumResolver transform fills it with the subject groups of the data source picked under Connect to EarthRanger (depends_on: properties.er_connection.properties.data_source.properties.name).
  • rjsf-overrides $defs limits the Category grouper to Subject Name (ValueGrouper.properties.index_name.oneOf), the only subject column the views are split on.
  • The steps are not in task groups, so each form override is keyed by its step id (e.g. subjectgroup_observations.properties.subject_group_name).
  • The Spatial grouper's Spatial Regions is still a text field. To make it a drop-down of the site's spatial feature groups, add an EarthRangerEnumResolver transform with type: spatial_feature_group on groupers.properties.groupers.
  • Open settings. Set Groupers and the Trajectory Segment Filter have no partial values, so they're on the form for each run. Without a ui:order, sections appear in the order of the steps.

How the night/day ratio is calculated

summarize_night_day_ratio (ecoscope-workflows-ext-custom) splits each subject's segments into local solar days and scores each one on its own. It compares speed, not distance, so long winter nights or short summer nights don't bias the result:

  • A solar day runs from local noon to local noon, so it holds one whole night. Local time comes from the segment's longitude (15° per hour). The day's solar_date is the date of the local midnight in it, so the night of 3–4 May is 4 May.
  • Night is when the sun is more than 6° below the horizon (civil twilight) at the solar day's position. Each segment's distance and observed hours are split between night and day by the share of its time that falls in that window.
  • For each solar day: night speed = night distance ÷ observed night hours, day speed = day distance ÷ observed day hours, and ratio = night speed ÷ day speed. 1 is balanced, above 1 faster at night, below 1 faster by day.
  • A solar day gets no ratio (NaN) unless it has more than 1 hour of observed data in both daylight and darkness, or when there was no daytime movement. The same happens on a day with no night at all, such as polar summer. Segments longer than 6 hours are dropped rather than split, because a long gap-bridging segment says nothing about speed within it. Exclude null values from night_day_ratio then removes these rows, plus days with a ratio of 0 (no night movement).

Why not summarize_df? Its night_day_ratio aggregator runs ecoscope's get_nightday_ratio on whatever rows it is given, so a per-date table would mean grouping segments by their UTC start date (segment_start_date). get_nightday_ratio already works in noon-to-noon solar days. Slicing its input at UTC midnight first cuts every night near longitude 0 in half, and each half can then fail the 1-hour coverage check, so nights go missing. summarize_night_day_ratio reuses ecoscope's noon-to-noon split and night-fraction helpers, but returns one row per solar day. For a single solar day, get_nightday_ratio's weighted share comes to the same night speed ÷ day speed. It also uses astropy's bundled IERS tables rather than downloading them, and it handles dusk or dawn falling in a leap second.

Two caveats from ecoscope: the ratio depends on fix rate, so don't compare collars with different duty cycles (coarser fixes pull the ratio towards 1), and it skews if a track crosses the −180/180° meridian. The is_night flag from Classify Is Night is kept in the saved data but isn't used by the ratio, which works out darkness itself.

Recompiling

spec.yaml is the source; ecoscope-workflows-subject-night-day-table-workflow/ is generated from it by wt-compiler.

./dev/recompile.sh --update   # keeps the lock file and bumps VERSION.yaml
./dev/recompile.sh --install  # a new lock file, and the packages installed

Testing

Each case in test-cases.yaml runs the workflow with its settings:

pixi run --manifest-path pixi.toml -e default bash dev/pytest-cli.sh subject_night_day_table --all
